# Shader-pack interface

Vulkanite 26.3 lets a shader pack request one Vulkan ray-tracing segment after a named Iris **COMPOSITE** pass. The pass first completes its Iris compute dispatch, barriers and optional raster draw. Vulkanite then runs the ray segment and returns its image to OpenGL before Iris continues with later composite passes and the standard final pass. Packs without ray stages and a Vulkanite declaration retain the ordinary Iris OpenGL path.

The pack must provide `shaders/vulkanite.properties` and contiguous `ray0.rgen`, `ray0_0.rmiss`, and hit shaders. There is no compatibility with the earlier sidecar or scene ABI. A minimal declaration is:

```properties
schema=2
sharedColorTargets=1
sceneGeometry=true
execution.phase=COMPOSITE
execution.after=composite
color.read=
color.write=0
storage.12.minimumBytes=512
```

`execution.after` names exactly one active Iris composite pass, including a compute-only pass. `sharedColorTargets` allocates a contiguous prefix of shared `colortex` targets; it does **not** grant the ray shader write access to every target in that prefix. `color.write` selects one logical target. Vulkanite binds its current physical main/alt image to the single set 0, binding 6 `rgba32f` storage image and traces at that image's dimensions. An empty `color.read` means no color input. A nonempty comma-separated list binds only those current physical images, in declaration order, to a set 0, binding 18 combined-image-sampler array of the same length. Reading and writing one logical target in place is rejected in this first contract. A pack must also declare each `storage.N.minimumBytes` as Iris `bufferObject.N`; the corresponding ray SSBO binding must exist, and its shared allocation must meet the declared capacity before dispatch. One SSBO-only descriptor set per ray pass is currently supported.

The physical side of a logical `colortex` is chosen from Iris's **current** ping-pong state after the named pass. It is not chosen from whether the target was ever flipped. A pack can place another Iris composite pass after the Vulkan segment; that pass reads the Vulkan result in the same frame. If the named pass is absent or runs twice, Vulkanite fails with an explicit contract error. Pack authors must declare a writable Iris target format matching the ray shader's storage-image format and ensure later passes/final sample the selected logical output.

## Camera and scene

Set 0 binding 0 is a 160-byte std140 host camera block: four `vec3` ray corners at bytes 0–63, `mat4 inverseView` at 64–127, `uint frame` at 128, `uint flags` at 132, padding to 144, and `uvec4 vulkaniteFrameAbi` at 144–159. The ABI version is 3. Vulkanite supplies only the camera data needed for rays and world-space scene coordinates. Pack-defined Iris uniforms, including custom ones, can be written into the declared SSBO by an ordinary composite compute pass. The pack owns that SSBO's field layout and validity checks; Vulkanite validates its binding and size, not the meaning of private fields.

`sceneGeometry=true` includes normal Sodium terrain and supported world draws submitted through Iris/RenderPearl. Set 0 binding 1 is the scene TLAS; set 1 binding 0 is the current geometry storage array. Terrain remains 64 bytes per vertex with the established quad winding. Dynamic scene vertices are an unindexed triangle list, 112 bytes per vertex. Iris quad draws are expanded as `(0,1,2)` and `(0,2,3)`; indexed triangle draws follow the producer's actual index order and base vertex. Set 0 binding 7 is the dynamic albedo array (256 entries); bindings 16/17 for normal/specular arrays are optional pack inputs.

| Byte offset | Dynamic vertex field |
| --- | --- |
| 0, 12, 16, 24 | World position `vec3`, RGBA8 color, UV0 `vec2`, world normal RGBA8_SNORM |
| 28, 32, 36 | Sampled texture slot `uint`, surface flags `uint`, selected material ID `int32` |
| 40, 48, 56 | UV1 and UV2 as two signed 32-bit components each, `mc_midTexCoord` as `vec2` |
| 64, 68, 84 | World tangent RGBA8_SNORM, all four raw `iris_Entity` signed 32-bit components, two raw `mc_Entity` signed 32-bit components |
| 92, 96, 100–111 | Raw `at_midBlock` RGBA8_SNORM, presence mask `uint`, reserved zeros |

The color and position data use the producer's real draw; normal and tangent are both mapped into world space. Normals use the inverse transpose, tangents use the forward linear transform (or observed hand-projection Jacobian), are orthogonalized to the normal, and flip handedness under a mirrored transform. Dynamic surface flags use bit 0 for camera-hidden body, bit 1 for view model, bit 2 for cutout coverage, bit 3 for particle, bit 4 for two-sided surface, and bit 5 for alpha blend. The selected material ID is a full signed 32-bit convenience value; the raw Iris/MC channels remain available for pack policy, including a mapped zero or a map miss. Presence bits 0–6 mark UV1, UV2, midTexCoord, tangent, iris_Entity, mc_Entity and midBlock. Bits 7–13 distinguish GL constant sources for those fields. Bits 14–17 mark color/normal presence and constant source. A zero value with its presence bit clear is **not** a producer value. The fourth Iris channel is retained as raw input without assigned semantics.

The terrain vertex carries Sodium's complete packed `a_LightAndData` at byte 16 (lightmap U/V in its low two bytes; remaining producer data bits retained), source mid-UV at 20 when Iris provides it (otherwise a generated midpoint), derived tangent at 24, derived normal at 28, decoded `mc_Entity` at 32 and source `at_midBlock` at 36 when available. Byte 40/44 in a canonical quad hold `layerStartWords`/`layerCount`, surface flags use 48 (bit 1 two-sided, bit 2 cutout, bit 3 alpha blend), validity/source bits use 52, the exact packed Iris `iris_Normal` source uses 56, and the original packed Sodium/Iris `mc_Entity` source uses 60 when provided. Terrain presence bits 0–7 mark source light, source mid-UV, derived mid-UV, derived tangent, derived normal, source `mc_Entity`, source `at_midBlock`, and source `iris_Normal`. Bit 8 identifies the actual Sodium Compact vertex type: only there does `a_LightAndData` byte 2 carry `Material.bits` (`mipped | alphaCutoff.ordinal << 1`); in Iris XHFP that byte instead carries tangent sign. The reference pack does not invent Compact cutoff bits when XHFP is active. Packs can inspect these inputs without assuming absent optional fields contain meaningful zeros.

Only quads with identical packed positions in the same four-corner order and the same facing normal can form a coplanar layer group. Group order follows Sodium's standard pass order (solid, cutout, translucent) and each pass's original quad order; unknown passes remain separate. `layerCount=0` means the canonical quad is the sole surface. For a multilayer group, `layerStartWords` indexes an appended, contiguous list of `layerCount` **complete original 64-byte-per-vertex quads** in the same owned geometry buffer; only the canonical quad contributes BLAS triangles. The reference pack composites the layers in order using each source texture alpha and vertex color. Its directory has no color-based grass/glass classification, and the original attributes of every layer remain addressable.

The public indexed-draw adapter accepts an OpenGL RenderPearl triangle submission with supported Position/UV0 vertex attributes, `Sampler0`, and standard `DynamicTransforms`. It reads the **actual backend pipeline** and the bindings used to create its VAO, including attributes supplied as per-draw GL constants rather than VBO bytes. A vertex field optimized out of the active shader can still come from the complete producer VertexFormat when its stride and active Position binding match the backend, and its bytes are proved to be non-dummy. It copies each version of the producer VBO, each referenced index slice and the per-draw transform into Vulkanite-owned staging while the producer buffers are valid; a bounded frame-level fence precedes CPU decoding. RenderPearl writes invalidate a reused VBO snapshot. It checks every unsigned index and `baseVertex`, then builds owned world-space triangles. Main and normal shadow submissions use their respective pass-view matrix and the unshifted camera origin; a main submission takes priority over a proven matching shadow submission, while unmatched shadow geometry remains available. Geometry never submitted by the upstream renderer is unavailable. Arbitrary vertex-shader displacement, custom transform semantics, nontriangle primitives and private GPU buffers without a supported copy path are not inferred from raw bytes. A material-map ID is not an object identity; a pack should use neutral treatment when no valid source ID is provided.

For supported 2D surfaces, the adapter retains the producer's `Sampler0` repeat/clamp, nearest/linear min/mag, mip LOD and supported anisotropy as an owned sampler state per material slot. Sodium's block atlas and its optional PBR atlas views use the actual atlas sampler by the same rule. A texture view must cover the complete underlying 2D texture; subset mip views, arrays, cube maps and unsupported texture formats fail explicitly rather than being sampled as a different image. The declared `color.read` images use Vulkanite's fixed nearest/clamp sampler; packs can use `texelFetch` for exact pixels. The reference pack treats cutout and alpha blend separately: cutout uses a fixed coverage threshold, alpha blend uses stochastic coverage proportional to source alpha. That is a basic path-tracing approximation, not exact custom blend equations, refraction or ordered transparent surfaces.

`sceneGeometry=false` disables normal scene capture but still uses this ray-stage executor and its declared color/storage resources. It is not a general replacement for Iris compute shaders. No DLSS, temporal reconstruction, SHaRC, external mesh-publishing API or legacy rigid-medium protocol is part of this interface.
