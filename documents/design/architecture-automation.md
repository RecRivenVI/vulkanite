# 自动化验证工具架构

`automation` 是项目的 `tool` 组件，为 Vulkanite 的客户端功能验证提供 Windows 自动化驱动。它启动隔离的客户端运行，与仅在验证运行中加载的 probe 入口交换诊断数据，并把一次验证的结果留在该验证自己的实例与结果目录中。

## 组成

自动化组件包含环境预检、空区段端到端验证与采样脚本。驱动通过 loopback IPC 与 probe 通信；授权令牌只用于当前运行。`src/probe/` 中的 `AuditEntrypoint` 提供被验证的诊断入口，按 V-06 只随验证运行加载，不进入产品 JAR。

## 隔离边界

每项自动化验证使用自己的临时实例与结果目录。驱动不启动、修改或读取使用者的 Prism 人工实例；人工画面与交互验收由使用者完成。自动化运行生成的实例与证据不视为产品状态或视觉验收。

Windows 驱动在验证实例中隐藏启动客户端，结束时等待该次启动的客户端与命令进程退出。IPC 绑定本机回环地址，不用作对外服务，也不代替游戏内行为的人工确认。

## 组件边界

自动化驱动、PowerShell/Python 脚本与采样工具都属于 `tool` 组件，不随模组发行。产品代码不依赖 probe 或自动化组件；验证由各自的验证说明规定命令、输入和通过标准。工具变更时，按对应验证的说明执行并保存结果。
