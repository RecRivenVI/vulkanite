# 动态几何与互操作开销调查

调查日期：2026-10-09。已减少动态几何重复转换、布局查询和上传区间对象，并以精确字节比较取代全量滚动哈希。新增的 OpenGL 时间戳把交接区间与 Vulkan 阶段区分开，但不能单独量化纯互操作损耗；本次前后场景几何量不同，也不能据此宣布确定的帧率提升。

## 问题

在保持光影质量与 32 视距的前提下，减少路径追踪着色以外的主机工作，并判断 OpenGL/Vulkan 信号提交是否存在明显的 CPU 阻塞。

## 方法

先只增加计时，在隔离主世界记录修改转换算法前的基线，再修改动态几何处理并运行相同验证世界。两轮均为 RTX 4080 SUPER、2560×1440、Foundation 默认每像素 2 采样、4 次反弹，视距与模拟距离均为 32。每个诊断模式预热 8 秒，测量 15 秒；窗口状态、原始计数与构件哈希随结果保存。

证据位于 `validations/performance-diagnostics/result/cpu-interop-baseline-20261009/` 和 `validations/performance-diagnostics/result/cpu-interop-optimized-20261009/`。第二轮完成后恢复详细诊断关闭。JFR 在仓库外采集，不在吞吐量测量窗口内运行。

通过单元测试核对四边形展开、全部顶点字段，以及世界、阴影和手臂在不同转换顺序下的字节一致性。另测快照独立所有权、哈希碰撞反例、GL 查询租约上限、窗口重置、未完成帧与实际时间戳位宽。执行空区段生命周期回归与发行检查。

## 发现

### 主机处理

四边形的四个原始顶点各转换一次，随后按既定绕序展开为六个三角形顶点。格式布局随组装器缓存、随管线释放；可见性分组只为实际连续区间创建上传记录。

动态几何快照持有独立的上帧字节，比较在首个差异处停止。发生变化时复制新字节供下一帧比较；构建失败会使快照失效。它增加一份主机侧顶点存储，没有增加 GPU 顶点存储，也没有改为按实体独立缓存：任一动态几何变化仍可能重建整个动态组。

基线的 CPU 窗口平均动态顶点量从约 4.9 万到 14.6 万变化，场景组装为 2.18–12.25 ms，TLAS 主机范围为 2.08–5.79 ms。优化后的窗口平均动态顶点量约 4.3–4.6 万，场景组装为 2.35–2.86 ms，TLAS 主机范围为 1.70–2.44 ms。因此这两轮不是严格固定几何的性能对照，不能把所有耗时变化归功于修改。

第二轮结束后的 20 秒 JFR 得到 732 个渲染线程执行样本。仍可见场景组装、转换、可见性分组，以及 Sodium 区段访问、Iris 顶点序列化；全量滚动哈希已从实现中移除。抽样栈存在内联与归因限制，不能把样本占比当作精确帧耗时。

### 互操作

第二轮两个完整诊断窗口的结果如下。CPU 数值按 PT 回调归一化，GPU 数值是各自完成样本的平均区间。

| 范围 | 窗口 2 | 窗口 4 |
| --- | --- | --- |
| CPU 场景组装 | 2.862 ms | 2.346 ms |
| CPU TLAS | 2.442 ms | 1.697 ms |
| CPU 信号提交与 flush | 0.234 ms | 0.154 ms |
| CPU 等待命令提交与 flush | 0.024 ms | 0.016 ms |
| CPU 回收 | 0.039 ms | 0.018 ms |
| GPU 光追 | 12.436 ms | 12.044 ms |
| GPU TLAS | 0.029 ms | 0.029 ms |
| GPU 动态 BLAS | 0.246 ms | 0.246 ms |
| OpenGL 世界开始到交接区间 | 14.572 ms | 10.100 ms |
| OpenGL 交接到 Vulkan 输出完成区间 | 14.712 ms | 13.287 ms |

CPU 交接调用在已测窗口中没有呈现长时间阻塞。但 GPU 交接区间包含 Vulkan 执行、CPU 提交间隙与依赖等待；不能把它全部当作互操作损耗，也不能与 Vulkan 区间直接相减。世界开始到交接的区间同样不是独占 OpenGL 着色时间。详细边界见[性能诊断](../development/debugging-performance.md)。

六个窗口均未暂停，分辨率与实际限帧上限保持一致；关闭模式没有详细时间或查询样本，GPU 查询失败数为零。第二轮关闭模式得到 25.81、30.47、33.96 次 PT 回调每秒；首个窗口仍在加载地形。这些计数不是实际显示帧率。

### 功能回归

21 个 Java 测试和 4 个采样统计测试通过。空区段首轮在世界仍加载时使用全局更新计数，出现无关非空更新增长。驱动补充有界的启动稳定等待后，`cpu-geometry-regression-20261009-b` 通过；产品区段逻辑未因此改变。该探针仍不能证明某一坐标的 holder 唯一性或定位过期 BLAS，自动化结果不等同于画面验收。

## 结论

本轮减少了明确的重复转换与对象创建，并消除了动态几何哈希碰撞造成错误复用的风险。画质参数、几何可见性与互操作的信号依赖保持不变；详细计时默认关闭，不为采样增加全局 GPU 等待。

当前证据支持继续检查 Iris/Sodium 世界输入与每帧动态组重建的工作量，不能证明互操作没有 GPU 成本。若继续追求可量化的性能改进，应先固定相机和动态几何输入，再比较同一负载；涉及跳过 OpenGL 世界绘制或改变 GPU 所有权的方案，需要另行验证生产者语义与同步正确性。
